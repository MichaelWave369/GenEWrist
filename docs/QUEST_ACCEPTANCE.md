# Physical Quest 3 acceptance — NOT COMPLETED

The 0.3.0 XR implementation is an experimental software candidate. Node fixtures and browser-generated synthetic stereo images do **not** establish physical device compatibility, comfort or frame rate.

Before release as a qualified headset integration, use the built HTTPS Pages console on a real Quest 3 and record browser/firmware versions, controller/hand mode, posture, observations and failures:

- [ ] Enter XR deliberately; confirm both eyes see correct, comfortable depth and legible text.
- [ ] Inspect the procedural case, bezel, strap, illuminated rings and optional synthwave dock.
- [ ] Raise the nonpointer wrist/controller in front at a comfortable distance. Check hand-adjacent placement, excessive proximity protection and tracking-loss fallback.
- [ ] Switch pointer handedness; test left-handed operation and controller fallback with optional hand input unavailable.
- [ ] Test right/left controller rays, target feedback, exact press/release selection and held-trigger entry suppression.
- [ ] Release/re-arm after tracking loss, input source replacement, visibility changes, recenter and context changes.
- [ ] Select all 3/6/9 rings, open actual modules and read full labels; test keyboard/focus alternatives in 2D.
- [ ] In World Mode, connect each explicitly simulated host, grant only a selected action, revoke, disconnect and return Home/Universal/Back.
- [ ] Test sculpt → paint context changes without reopening. Verify controls and fields from the previous context disappear.
- [ ] Use SIGL stamps/save, DriftRocks, GlowMotes and Laughter Forge in XR; continue writing JourneyLog in the clearly identified desktop editor.
- [ ] Check Glance/Field activation, squeeze fallback, Close, Home, Back, Cancel, Recenter and Exit XR.
- [ ] Check seated/standing dock choices, reduced motion, enlarged text/contrast, glare, fatigue and controller reach.
- [ ] Select an external world and cancel. Confirm that a deliberate final confirmation ends XR before navigation and that the next site needs its own immersive entry.
- [ ] End via both the UI and Quest system menu. Check that host controls/grants/subscriptions disappear, browser controls recover and repeat entry works.
- [ ] Reload the cached built console offline; exercise creative tools and export without external services.
- [ ] Test 15+ minutes of actual frame pacing, thermal behavior, memory and battery use. Record measurements rather than infer performance from desktop render counters.
- [ ] Separately integrate and test BTM in its own PR; preserve combat input suppression, neutral re-arm, weapons, map, Ori, checkpoints and travel.

No physical headset was available for this implementation. Calibrated forearm registration, continuous custom gesture recognition and genuine shared-host in-session portals are not claimed.
